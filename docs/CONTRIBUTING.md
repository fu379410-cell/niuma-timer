# 一起让牛马过得好一点

欢迎提交问题、文案建议和 Pull Request。项目采用 [MIT License](../LICENSE)。

## 开始开发

1. Fork 仓库，创建一个描述改动的分支。
2. 使用 Node.js 22.12+（推荐 24），执行 `npm ci`。
3. 执行 `npm run dev`；桌面开发另开终端执行 `npm run desktop:dev`。
4. 完成改动后运行与本次改动相称的验证；提交前至少通过 `npm test` 和 `npm run build`。

## 代码放在哪里

| 路径 | 职责 |
| --- | --- |
| `src/main.js` | 页面、交互和本地配置 |
| `src/style.css` | 磨砂玻璃视觉与响应式布局 |
| `src/lib/salary.mjs` | 无依赖的薪资、工时与日期计算 |
| `src/lib/*.test.mjs` | Node.js 计算测试 |
| `electron/` | 桌面窗口和受限 IPC 接口 |
| `public/` | 应用使用的静态素材 |
| `design/` | 视觉原型与 imagegen 提示词 |
| `.github/workflows/` | 持续检查和安装包构建 |

## 改动约定

- 保持「精致但有点发疯」的气质，文案关照打工人，避免羞辱或制造焦虑。
- 计算规则保持透明。修改薪资逻辑时添加对应的边界测试，并同步更新 README 中的计算口径。
- 保持本地优先；不要在没有明确产品约定的情况下增加账号、遥测或工资数据上传。
- 界面改动兼顾键盘操作、窄屏、金额隐藏与迷你窗口。请附修改后的截图。
- Electron 不暴露原始 IPC、Node.js 或任意系统命令；新增桌面能力时继续校验调用来源与参数。
- 新增图片、字体或其他外部资源时注明来源与许可；不要提交密钥、个人配置、依赖目录或构建产物。

## 提交问题与 PR

问题中写清操作步骤、预期结果、实际结果、系统与应用版本。涉及计算时，请给出不含隐私的配置和具体时间。

PR 描述说明改了什么、为什么、如何验证。请区分已经实际运行的平台与仅由工作流构建的平台。

## 发布

维护者更新 `package.json` 版本和锁文件后，推送匹配的 `v版本号` 标签。工作流先测试和构建，再分别生成 Windows x64、macOS arm64 和 macOS x64 安装包并上传到 GitHub Releases。手动执行 `Desktop release` 工作流只生成可下载的 artifacts，不创建 Release。

当前社区安装包未签名、macOS 未公证；发布说明应保留这一事实。涉及签名或公证的后续配置应使用 GitHub Secrets，不把凭据写进仓库。
